# RemoteFamily Milestone 0.1.0 Design

## Objective

Create the smallest reproducible Android foundation for RemoteFamily and prove that GitHub Actions can build an installable debug APK without an Android SDK, Android Studio, Kotlin, or Gradle installed on the developer workstation.

This design covers only Milestone 0.1.0. It does not include the server, networking, WebRTC, MediaProjection, AccessibilityService, permissions, sessions, navigation, or infrastructure.

## Decisions

- One Android application module named `app` under `android/`.
- Application ID and namespace: `com.remotefamily.app`.
- Application label: `RemoteFamily`.
- Android Gradle Plugin: `9.3.1`.
- Gradle Wrapper: `9.5.0`.
- Build JDK: `17`.
- Built-in Kotlin `2.2.10` support from AGP 9.3.1; do not apply `org.jetbrains.kotlin.android`.
- Compose Compiler Gradle plugin: `2.2.10`, matching the Kotlin compiler bundled with AGP 9.3.1.
- Gradle Kotlin DSL with versions declared directly in build files.
- `compileSdk = 36`, `targetSdk = 36`, and `minSdk = 24`.
- Compose BOM: `2026.06.00`. Compose BOM `2026.08.00` is excluded because its Compose 1.12 artifacts require `compileSdk 37`, while this milestone intentionally preserves the roadmap baseline of `compileSdk 36`.
- Activity Compose: `1.13.0`.
- Core KTX: `1.17.0`. Core KTX `1.19.0` is excluded because it and its Core dependency require `compileSdk 37`, while this milestone intentionally preserves `compileSdk 36`.
- No version catalog, convention plugin, dependency injection, navigation framework, or architecture layer in this milestone.
- The roadmap remains at `docs/REMOTEFAMILY_ROADMAP.md` as the single source of truth.

## Application Behavior

Android launches `MainActivity`. The activity uses Jetpack Compose to render a single simple screen with `RemoteFamily` centered on the screen.

There is no navigation, state persistence, network access, permission request, remote-control behavior, decorative animation, or future-milestone placeholder.

A small pure Kotlin identity/presentation unit supplies the application name. Its unit test establishes a real behavior that can be exercised by the CI without an emulator or Android device. Production behavior must be implemented through a red-green-refactor cycle: write and observe the failing unit test before adding the minimal implementation.

## Build Configuration

The repository versions the complete Gradle Wrapper, including scripts, properties, and wrapper JAR. Builds use the wrapper only; they must not rely on globally installed Gradle or Kotlin.

Repositories are limited to `google()` and `mavenCentral()`. Dependencies use fixed versions or the fixed Compose BOM. Dynamic selectors such as `+` and `latest.release` are forbidden.

The application is configured for Java 17 source and target compatibility. Compose is enabled only for the application module. Debug builds use the default Android debug signing configuration and require no secret.

## Continuous Integration

`.github/workflows/android-ci.yml` runs on:

- pushes to `main` that modify `android/**` or the workflow;
- pull requests that modify `android/**` or the workflow;
- manual `workflow_dispatch` runs.

The job runs on a GitHub-hosted Ubuntu runner and performs these operations in order:

1. Check out the repository using an action pinned to an immutable commit SHA.
2. Configure Temurin JDK 17 using an action pinned to an immutable commit SHA.
3. Configure Gradle caching and wrapper validation using an action pinned to an immutable commit SHA.
4. Make `android/gradlew` executable.
5. Run `./gradlew testDebugUnitTest`.
6. Run `./gradlew lintDebug`.
7. Run `./gradlew assembleDebug`.
8. Upload the generated APK as the `remote-family-debug` artifact using an action pinned to an immutable commit SHA.

If tests, lint, or assembly fails, the job fails and no APK is presented as a successful result. Test and lint reports are uploaded on failure so problems can be diagnosed without a local Android toolchain.

The expected APK path is:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

## Validation and Definition of Done

The implementation may be reviewed locally through static file inspection, wrapper checksum inspection, and workflow syntax inspection. The workstation is not expected to execute the Android build.

Milestone 0.1.0 is complete only when all of the following are true:

1. The Android project and Gradle Wrapper are committed.
2. GitHub Actions completes unit tests, lint, and debug assembly successfully.
3. The `remote-family-debug` artifact contains an installable APK.
4. The APK is installed on a physical Android device.
5. Launching the APK displays `RemoteFamily` without crashing.
6. The physical test result is recorded in project documentation.
7. No secret is committed and no future milestone functionality is present.

Until the CI and physical-device checks succeed, implementation can be described as prepared or awaiting validation, but the milestone must not be declared complete.

## Explicit Non-Goals

- Server or database code.
- Device registration or authentication.
- WebSocket signaling.
- WebRTC or TURN dependencies.
- AccessibilityService.
- MediaProjection or foreground services.
- Runtime permissions.
- Onboarding, device lists, or controller UI.
- Release signing or GitHub Releases.
- Android TV support.
